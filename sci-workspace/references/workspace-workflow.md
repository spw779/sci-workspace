# 工作区搭建与旧项目适配

## 新项目

确认目标路径，浅层查看已有内容。是否存在 Git 仓库不能单独判断一个目录是不是空项目，也不要求论文必须使用 Git。

执行 `workspace.py init` 创建五个顶层目录及缺失的两份说明。只按已知事实填写 Guide；期刊、完整研究计划和所有实验结果均不是初始化前置条件。章节通过 `--sections` 按需增加；材料分类通过 `--with-subdirs` 按需增加。选项不会删除已有目录。

使用模板 `assets/AGENTS.template.md` 和 `assets/WORKSPACE_GUIDE.template.md`。脚本先检查计划中的路径与模板，再写入；路径被错误类型的文件占用、或符号链接使输出越出项目时，报告具体冲突，不能覆盖或自行移走该项。

重复运行仅补缺。可选的 `--dry-run` 使用同一计划进行零写入预览，无须在每次运行前强制预览或询问许可。没有 Python 时，可按同样的预检、不覆盖和结果核对约定使用环境已有的文件工具完成搭建，不为此自动安装环境。

## 旧项目

先读已有指南，检查顶层及相关一层子目录。只关注本次搭建涉及的结构，不遍历全部数据或转换文献。

- 采用标准名称的项目：脚本补齐缺失项，已有 Guide 和 AGENTS 原文保留。保留文件不代表已经把新约定合入旧指南，报告时区分这两件事。
- 采用其他名称的项目：先核对已有用途和项目记录。例如 `data/` 可能已承担 `04_data/` 的职责；在 Guide 的目录表中记录真实路径，必要时直接补少量缺失目录。不要在未厘清用途时运行固定布局初始化，造成两套平行结构。
- 同时存在多个候选路径：保留现状，先报告实际目录及用途不明之处。用户已明确指定的位置优先；无法从材料判断且下一步会搬移文件时再询问具体选择。
- 用户要求修改已有说明时：基于原文做局部更新，保留已有项目事实和必要规则。大量改写前保留可恢复副本；不把整个文件替换为通用模板。

初始化和结构检查默认不搬运、重命名、清洗或重算研究文件。收到明确的材料整理请求后，按该任务选择相应能力与写入范围。已有证据表、结果索引、版本记录继续保留，本 skill 不要求为初始化新建这些文件。

## 检查与交付

`status` 报告标准结构中的已存在、缺失和类型冲突；列出已有章节及常用材料子目录。可选章节或子目录不存在不是错误。对于自定义布局，按 Guide 的实际路径解释检查结果，不机械把标准名称缺失当成项目损坏。

在初始化后核对计划中的目录和说明是否存在、已有文件是否被保留。输出简短清单，说明真正创建或复用的内容，以及未解决的路径冲突。只创建了目录时，不声称完成了数据整理、文献核验或论文写作。
